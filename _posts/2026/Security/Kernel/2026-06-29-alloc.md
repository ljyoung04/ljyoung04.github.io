title: 간단하게 알아보는 커널 메모리 할당 과정
date: 2026-06-29 21:14:25 +0900

---

Cross Cache Attack을 배우기 앞서 커널에서의 메모리 할당 과정을 이해하고 있어야 하기 때문에,
간단하게 정리해보도록 하겠다.


![1](/assets/img/2026/alloc/1.png)

kmalloc-192 캐시의 상황이 위와 같다고 하자.
F는 Freed를 의미하고, 회색은 in-used를 뜻한다.

저 상태에서는 1,2,3,4.. 순서대로 할당이 된다.

![2](/assets/img/2026/alloc/2.png)

`kmalloc(192)`을 3번 한 경우, `percpu active slab`이 꽉 차게 되고, `percpu partial slab`이 `percpu active slab`에 오게된다. 

그리고 4번째 `kmalloc(192)`를 할 경우 이 slab에 할당된다.

![3](/assets/img/2026/alloc/3.png)

만약 percpu active, partial slab을 모두 쓴 경우에는 `node partial slab`을 가져와서 사용한다.

![4](/assets/img/2026/alloc/4.png)

이것도 다 쓴다면, 버디 할당자를 통해 새로운 페이지를 할당받아서 사용하게 된다.


---

마지막으로 커널 메모리 할당에서 중요한 점이 하나 더 있다.

```c
ptr1 = kmalloc(192) // vuln
kfree(ptr1)
ptr2 = kmalloc(192) // target
```
만약 위처럼 메모리를 할당하게 된다면
`ptr1==ptr2`이 된다.

이들을 종합하면 `Cross Cache Attack`이라는 강력한 기법을 사용할 수 있게 된다.
