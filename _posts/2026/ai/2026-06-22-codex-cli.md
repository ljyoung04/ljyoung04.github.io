Codex CLI는 터미널에서 실행하는 OpenAI의 코딩 에이전트다. 로컬 저장소를 읽고, 파일을 수정하고, 필요한 명령을 실행하면서 작업을 진행할 수 있다. 터미널 안에서 바로 대화하고 변경사항을 확인하는 방식이라, 작은 질문부터 코드 수정, 리뷰, 자동화까지 한 흐름으로 처리하기 좋다.

공식 문서 기준으로 정리한 내용이다.

- [Codex CLI](https://developers.openai.com/codex/cli)
- [Codex CLI features](https://developers.openai.com/codex/cli/features)
- [Command line options](https://developers.openai.com/codex/cli/reference)
- [Slash commands in Codex CLI](https://developers.openai.com/codex/cli/slash-commands)

## 1. 설치 및 실행

macOS/Linux에서는 standalone installer로 설치한다.

```bash
curl -fsSL https://chatgpt.com/codex/install.sh | sh
```

처음 실행할 때는 ChatGPT 계정 또는 API key로 로그인한다.

```bash
codex
```

초기 프롬프트를 바로 넘겨서 시작할 수도 있다.

```bash
codex "이 코드베이스 구조를 설명해줘"
```

업데이트는 설치 스크립트를 다시 실행하면 된다.

```bash
curl -fsSL https://chatgpt.com/codex/install.sh | sh
```

## 2. 기본 작업 방식

`codex`를 실행하면 전체 화면 터미널 UI(TUI)가 열린다. 이 모드에서는 프롬프트, 코드 조각, 스크린샷을 입력하고 Codex가 제안하는 계획과 변경사항을 보면서 승인하거나 거절할 수 있다.

자주 쓰는 흐름은 다음과 같다.

- 코드 설명: `codex "이 모듈의 책임과 주요 흐름을 설명해줘"`
- 버그 수정: 문제 상황과 재현 방법을 설명하고 수정 요청
- 테스트 작성: 변경하고 싶은 동작을 설명한 뒤 테스트 추가 요청
- 리팩터링: 범위와 유지해야 할 동작을 지정
- 리뷰: `/review` 또는 `codex review`로 diff 검토

작업이 길어졌다면 `codex resume`으로 이전 세션을 다시 열 수 있다.

```bash
codex resume
codex resume --last
codex resume --all
codex resume <SESSION_ID>
```

비대화형 실행도 이어받을 수 있다.

```bash
codex exec resume --last "아까 찾은 race condition을 수정해줘"
```

## 3. 핵심 기능

### 모델과 reasoning 선택

모델은 실행 시점에 지정하거나 세션 중 `/model`로 바꿀 수 있다.

```bash
codex --model <MODEL_NAME>
```

작업 성격에 따라 빠른 모델, 더 깊은 reasoning 모델을 선택한다. 간단한 질의나 코드 설명은 빠른 모델로 충분하고, 큰 리팩터링이나 여러 파일을 건드리는 작업은 reasoning이 강한 모델이 유리하다.

### 이미지 입력

스크린샷, 에러 화면, 디자인 시안 등을 첨부해 함께 분석시킬 수 있다.

```bash
codex -i screenshot.png "이 에러의 원인을 설명해줘"
codex --image img1.png,img2.jpg "두 다이어그램의 차이를 요약해줘"
```

UI 버그, 디자인 구현, 콘솔 에러 캡처처럼 텍스트만으로 설명하기 어려운 상황에서 유용하다.

### 이미지 생성

CLI 안에서 아이콘, 배너, 일러스트, 스프라이트, placeholder 이미지 같은 에셋 생성을 요청할 수 있다. 기존 이미지를 기준으로 수정하고 싶다면 reference 이미지를 첨부해서 지시한다.

```text
블로그 썸네일용 Codex CLI 일러스트를 만들어줘
```

### 로컬 코드 리뷰

`/review`를 사용하면 현재 diff를 별도 reviewer 에이전트가 읽고 우선순위가 있는 finding 형태로 알려준다. 커밋 전 체크용으로 좋고, Codex가 직접 파일을 수정하지 않고 리뷰만 한다는 점이 편하다.

```text
/review
```

### 웹 검색

Codex CLI에는 웹 검색 도구가 있다. 기본은 캐시된 검색 결과를 사용하고, 최신 정보가 필요한 경우 `--search`를 붙이거나 설정에서 live web search를 켤 수 있다.

```bash
codex --search "최신 Next.js 마이그레이션 가이드를 확인해서 이 프로젝트에 필요한 변경점을 정리해줘"
```

문서, 최신 릴리스, API 변경사항처럼 모델 지식만으로는 위험한 작업에 붙여 쓰면 좋다.

### Subagents

큰 작업을 병렬로 나누고 싶을 때 subagent를 사용할 수 있다. 예를 들어 한 agent는 테스트 실패를 분석하고, 다른 agent는 UI 변경 범위를 조사하게 하는 식이다. 다만 각 subagent가 별도로 모델과 도구를 사용하므로 토큰 사용량이 늘어난다.

### MCP

MCP(Model Context Protocol)를 설정하면 Codex가 외부 도구나 추가 컨텍스트에 접근할 수 있다. `~/.codex/config.toml`에 서버를 등록하거나 `codex mcp` 명령으로 관리한다.

```bash
codex mcp list
```

내부 문서, 이슈 트래커, 데이터베이스, 사내 도구처럼 Codex가 직접 접근해야 하는 컨텍스트가 있을 때 특히 중요하다.

### Feature flags

실험적 또는 선택 기능은 `features` subcommand로 확인하고 켜고 끌 수 있다. 변경사항은 `$CODEX_HOME/config.toml`에 저장된다.

```bash
codex features list
codex features enable <feature>
codex features disable <feature>
```

## 4. 자주 쓰는 CLI 옵션

### 작업 디렉터리 지정

현재 위치를 바꾸지 않고 Codex의 작업 루트를 지정한다.

```bash
codex --cd apps/frontend
codex -C apps/frontend "빌드 에러를 확인해줘"
```

### 추가 디렉터리 접근 허용

여러 프로젝트나 shared 패키지를 함께 수정해야 할 때 사용한다.

```bash
codex --cd apps/frontend --add-dir ../backend --add-dir ../shared
```

### 승인 정책 지정

Codex가 명령 실행 전에 언제 사용자 승인을 받을지 정한다.

```bash
codex --ask-for-approval on-request
codex -a never "테스트를 실행하고 실패 원인을 요약해줘"
```

자동화에서는 `never`가 편할 수 있지만, 로컬 개발에서는 보통 `on-request`가 안전하다.

### Sandbox 모드 지정

모델이 생성한 shell command가 접근할 수 있는 범위를 정한다.

```bash
codex --sandbox read-only
codex --sandbox workspace-write
```

- `read-only`: 파일 읽기 중심. 상담, 분석, 리뷰에 적합하다.
- `workspace-write`: 현재 작업 디렉터리 안에서 수정 가능. 일반 개발 작업에 적합하다.
- `danger-full-access`: 더 넓은 접근 권한. 신뢰할 수 있는 환경에서만 사용한다.

### 설정 오버라이드

한 번의 실행에만 설정값을 덮어쓴다. 값은 TOML로 해석 가능한 경우 TOML로 처리된다.

```bash
codex -c model_reasoning_effort='"high"'
codex -c web_search='"live"' "최신 문서를 확인하고 마이그레이션 계획을 세워줘"
```

### 이미지 첨부

```bash
codex -i error.png "이 화면에서 무엇이 문제인지 분석해줘"
```

### Live web search

```bash
codex --search "공식 문서를 확인해서 현재 API 사용법을 정리해줘"
```

### 위험 옵션

`--dangerously-bypass-approvals-and-sandbox` 또는 `--yolo`는 승인과 sandbox를 모두 우회한다. 격리된 runner나 폐기 가능한 환경이 아니라면 사용하지 않는 편이 좋다.

```bash
codex --yolo "반복 작업을 자동으로 처리해줘"
```

## 5. 비대화형 실행: `codex exec`

스크립트나 CI처럼 사람이 중간에 개입하지 않는 작업에는 `codex exec`를 쓴다. 짧게 `codex e`로도 실행할 수 있다.

```bash
codex exec "현재 diff를 리뷰하고 위험한 변경사항만 요약해줘"
codex e "테스트 실패 원인을 찾아줘"
```

표준 입력에서 프롬프트를 받을 수도 있다.

```bash
cat prompt.md | codex exec -
```

자동화에 유용한 옵션은 다음과 같다.

```bash
codex exec --json "lint 실패 원인을 찾아줘"
codex exec --output-last-message result.md "이번 변경사항을 릴리스 노트로 정리해줘"
codex exec --output-schema schema.json "결과를 JSON으로 반환해줘"
codex exec --skip-git-repo-check "이 디렉터리의 파일 구조를 요약해줘"
```

- `--json`: newline-delimited JSON 이벤트 출력
- `--output-last-message`: 마지막 응답을 파일로 저장
- `--output-schema`: 최종 응답을 JSON Schema에 맞게 검증
- `--ephemeral`: 세션 rollout 파일을 디스크에 남기지 않음
- `--skip-git-repo-check`: Git 저장소가 아닌 디렉터리에서도 실행

## 6. 유용한 subcommand

공식 reference에서 특히 자주 쓸 만한 명령은 다음과 같다.

| 명령 | 용도 |
| --- | --- |
| `codex` | 대화형 TUI 실행 |
| `codex exec` / `codex e` | 비대화형 실행 |
| `codex resume` | 이전 세션 이어가기 |
| `codex review` | 코드 리뷰 실행 |
| `codex features` | feature flag 확인/변경 |
| `codex mcp` | MCP 서버 관리 |
| `codex doctor` | 설치, 설정, 인증, Git, 터미널 문제 진단 |
| `codex completion` | shell completion 생성 |
| `codex apply` | Codex Cloud task의 최신 diff를 로컬에 적용 |
| `codex cloud` | 터미널에서 Codex Cloud task 실행/조회 |
| `codex plugin` | 플러그인 설치, 목록, 제거 |
| `codex update` | 지원되는 설치 환경에서 CLI 업데이트 |

## 7. Slash commands

대화형 세션 안에서는 `/`를 입력해 slash command popup을 열 수 있다. 작업 중에도 명령을 입력하고 `Tab`을 누르면 다음 턴에 실행되도록 queue할 수 있다.

### 세션 제어

| 명령 | 용도 |
| --- | --- |
| `/clear` | 터미널을 지우고 새 대화 시작 |
| `/copy` | 최신 완료 응답 복사 (`Ctrl+O`) |
| `/compact` | 긴 대화를 요약해 context 확보 |
| `/diff` | Git diff와 untracked file 확인 |
| `/exit`, `/quit` | CLI 종료 |
| `/fork` | 현재 대화를 새 thread로 분기 |
| `/side`, `/btw` | 메인 transcript를 흐트러뜨리지 않는 짧은 side conversation |
| `/resume` | 저장된 대화 이어가기 |

### 모델, 권한, 작업 방식

| 명령 | 용도 |
| --- | --- |
| `/model` | 활성 모델과 reasoning effort 선택 |
| `/fast` | 지원 모델에서 Fast tier 켜기/끄기/상태 확인 |
| `/permissions` | 승인 정책 변경 |
| `/approve` | 자동 리뷰가 막은 최근 action을 한 번 재시도 |
| `/plan` | 구현 전에 plan mode로 전환 |
| `/goal` | 긴 작업의 목표 설정/조회/일시정지/재개/삭제 |
| `/personality` | 응답 스타일 변경 |

### 도구와 컨텍스트

| 명령 | 용도 |
| --- | --- |
| `/mention` | 파일이나 폴더를 대화에 첨부 |
| `/mcp` | 현재 설정된 MCP 도구 확인 |
| `/apps` | connector/app을 prompt에 첨부 |
| `/plugins` | 플러그인 확인/설치/관리 |
| `/skills` | 로컬 skill 선택 |
| `/hooks` | lifecycle hook 확인/신뢰/비활성화 |
| `/ide` | IDE의 열린 파일, 선택 영역 등 context 포함 |

### 환경, 진단, UI

| 명령 | 용도 |
| --- | --- |
| `/status` | 모델, 승인 정책, writable root, token usage 등 세션 상태 확인 |
| `/usage` | token activity 확인 |
| `/debug-config` | config layer와 policy source 진단 |
| `/statusline` | TUI footer 항목 설정 |
| `/title` | 터미널 title 항목 설정 |
| `/theme` | syntax highlighting theme 선택 |
| `/keymap` | TUI shortcut 재매핑 |
| `/vim` | composer Vim mode 토글 |
| `/ps` | background terminal 상태 확인 |
| `/stop` | background terminal 중지 |

## 8. 작업할 때 유용한 습관

### 1. 시작 전에 환경을 맞춘다

가상환경, package manager, 필요한 daemon, 환경변수는 Codex 실행 전에 준비한다. 그래야 Codex가 환경을 추측하는 데 시간을 쓰지 않고 바로 작업할 수 있다.

```bash
source .venv/bin/activate
export OPENAI_API_KEY=...
codex
```

### 2. 파일을 명시한다

composer에서 `@`를 입력하면 workspace root 기준으로 파일 검색을 열 수 있다. 관련 파일을 직접 mention하면 Codex가 불필요하게 저장소 전체를 훑는 일을 줄일 수 있다.

```text
@app/api/users/route.ts 이 엔드포인트의 validation을 강화해줘
```

### 3. 긴 작업은 계획부터 요구한다

여러 파일을 바꾸는 작업이라면 바로 구현시키기보다 먼저 `/plan`으로 접근 방법을 확인한다.

```text
/plan 이 결제 모듈을 새 provider 인터페이스에 맞게 마이그레이션하는 계획을 세워줘
```

### 4. 리뷰와 diff 확인을 습관화한다

작업 후에는 `/diff`로 변경 범위를 보고, 커밋 전 `/review`로 별도 reviewer에게 확인시키는 흐름이 좋다.

```text
/diff
/review
```

### 5. context가 길어지면 compact한다

대화가 길어져 모델이 앞부분을 잊거나 토큰 사용량이 커질 것 같으면 `/compact`로 요약한다. 중요한 결정, 변경 파일, 남은 TODO를 유지하면서 context를 줄일 수 있다.

```text
/compact
```

## 9. 예시 워크플로우

### 코드베이스 파악

```bash
codex "이 저장소의 구조, 주요 entrypoint, 테스트 실행 방법을 요약해줘"
```

### 버그 수정

```bash
codex --cd apps/web "로그인 후 redirect가 잘못되는 문제를 재현하고 수정해줘. 수정 후 관련 테스트도 실행해줘"
```

### 최신 문서 확인 후 마이그레이션

```bash
codex --search "공식 문서를 확인해서 현재 Next.js 버전에 맞는 마이그레이션 계획을 세워줘"
```

### CI용 리뷰 자동화

```bash
codex exec --json "현재 PR diff를 리뷰하고 심각한 버그만 JSON으로 출력해줘"
```

### UI 스크린샷 분석

```bash
codex -i screenshot.png "이 화면에서 레이아웃이 깨지는 원인을 찾고 수정해줘"
```

## 정리

Codex CLI는 단순한 채팅 도구라기보다 터미널 기반 로컬 코딩 에이전트에 가깝다. 평소에는 `codex`로 대화형 TUI를 쓰고, 반복 작업이나 CI에서는 `codex exec`를 쓰는 식으로 나누면 좋다.

가장 먼저 익혀둘 만한 것은 `--cd`, `--add-dir`, `--model`, `--sandbox`, `--ask-for-approval`, `--search`, `/model`, `/permissions`, `/diff`, `/review`, `/compact`, `/status`다. 이 정도만 익혀도 대부분의 로컬 개발 작업에서 Codex CLI를 꽤 효율적으로 사용할 수 있다.
