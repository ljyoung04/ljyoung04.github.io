## TCP/IP

### DNS(Domain Name System)
DNS TTL : 데이터가 DNS서버 캐시로부터 나오기 전에 현재 남은 시간을 의미

| 레코드 | 의미 | 설명 | 예시 |
|---|---|---|---|
| A | Address | 도메인 이름을 IPv4 주소로 매핑 | `example.com → 93.184.216.34` |
| AAAA | IPv6 Address | 도메인 이름을 IPv6 주소로 매핑 | `example.com → 2606:2800:220:1:248:1893:25c8:1946` |
| CNAME | Canonical Name | 도메인 별칭 설정 | `www.example.com → example.com` |
| MX | Mail Exchange | 메일 서버 지정 | `example.com → mail.example.com` |
| NS | Name Server | 해당 도메인을 관리하는 네임서버 지정 | `example.com → ns1.example.com` |
| SOA | Start of Authority | DNS 존의 기본 정보 저장 | 관리자, 시리얼 번호, 갱신 주기 등 |
| PTR | Pointer | IP 주소를 도메인 이름으로 역방향 조회 | `93.184.216.34 → example.com` |
| TXT | Text | 텍스트 정보 저장 | SPF, DKIM, 도메인 인증 등에 사용 |
| SRV | Service | 특정 서비스의 서버 위치 지정 | SIP, LDAP, Kerberos 등 |

### IPv4 Class

| 클래스 | 시작 비트 | 주소 범위 | 기본 서브넷 마스크 | CIDR | 용도 |
|---|---|---|---|---|---|
| A Class | 0 | 0.0.0.0 ~ 127.255.255.255 | 255.0.0.0 | /8 | 대규모 네트워크 |
| B Class | 10 | 128.0.0.0 ~ 191.255.255.255 | 255.255.0.0 | /16 | 중규모 네트워크 |
| C Class | 110 | 192.0.0.0 ~ 223.255.255.255 | 255.255.255.0 | /24 | 소규모 네트워크 |
| D Class | 1110 | 224.0.0.0 ~ 239.255.255.255 | - | - | 멀티캐스트 |
| E Class | 1111 | 240.0.0.0 ~ 255.255.255.255 | - | - | 실험용/예약 |

### OSPF

동적 라우팅 프로토콜로, Link State 알고리즘을 사용하여 서로에게 자신의 현재 상태를 알려주며, 네트워크 내 통신을 위해 사용된다.

### IPv4 header

| 필드 | 크기 | 설명 |
|---|---:|---|
| Version | 4 bits | IP 버전. IPv4는 `4` |
| IHL | 4 bits | IP 헤더 길이. 옵션 없으면 보통 `20 bytes` |
| DSCP / ECN (ToS) | 8 bits | 서비스 품질, 혼잡 제어 관련 필드 |
| Total Length | 16 bits | IP 헤더 + 데이터 전체 길이 |
| Identification | 16 bits | 단편화된 패킷을 재조립할 때 식별용 |
| Flags | 3 bits | 단편화 제어. `DF`, `MF` 등이 있음 |
| Fragment Offset | 13 bits | 단편화된 조각의 위치 |
| TTL | 8 bits | 패킷 생존 시간. 라우터를 지날 때마다 1씩 감소 |
| Protocol | 8 bits | 상위 계층 프로토콜 표시. TCP=`6`, UDP=`17`, ICMP=`1` |
| Header Checksum | 16 bits | IP 헤더 오류 검사용 체크섬 |
| Source IP Address | 32 bits | 출발지 IP 주소 |
| Destination IP Address | 32 bits | 목적지 IP 주소 |
| Options | 가변 | 선택 필드. 거의 사용되지 않음 |
| Padding | 가변 | 헤더 길이를 32비트 단위로 맞추기 위한 패딩 |

### MTU(Maximum Transmission Unit)
IP 패킷은 네트워크 유형에 따라 전송량에 차이가 있기 때문에 MTU를 기준으로 적당한 크기로 분할한다.

### SNMP 
네트워크 장비를 관리, 감시하기 위한 프로토콜.
UDP를 사용한다. 

### ICMP
IP 통신 중 발생하는 오류 보고, 진단용 프로토콜

| Type | Code | 이름 | 설명 |
|---:|---:|---|---|
| 0 | 0 | Echo Reply | `ping` 응답 |
| 3 | 0 | Destination Network Unreachable | 목적지 네트워크 도달 불가 |
| 3 | 1 | Destination Host Unreachable | 목적지 호스트 도달 불가 |
| 3 | 2 | Protocol Unreachable | 목적지에서 해당 프로토콜 사용 불가 |
| 3 | 3 | Port Unreachable | 목적지 포트 도달 불가. 주로 UDP에서 사용 |

| 5 | 0 | Redirect Network | 더 좋은 네트워크 경로로 리다이렉트 |
| 5 | 1 | Redirect Host | 더 좋은 호스트 경로로 리다이렉트 |
| 8 | 0 | Echo Request | `ping` 요청 |

| 13 | 0 | Timestamp Request | 타임스탬프 요청 |
| 14 | 0 | Timestamp Reply | 타임스탬프 응답 |

### 패킷 교환 방식
- 가상 회선 방식 : 패킷 전송 전 송, 수신 측 간 논리적인 경로가 사전에 성림. 종단 간 연결이 설정되면 데이터 흐름이 이 연결을 통해서만 흐르게 됨, 연결 지향성
- 데이터그램 : 각 패킷이 독립적으로 처리되어 목적지까지 도달. 각 패킷들을 독립적으로 처리. 순서와 무관하게 전달. 목적지가 같은 패킷이어도 항상 같은 경로는 아니다.


### 통신망

- 버스형 <br>
한 통신회선에 여러 단말기들을 연결 <br>
장점 : 노드의 추가, 삭제가 용이 <br>
단점 : 노드 증가 시 효율 떨어짐 <br>

- 스타형 <br>
호스트 중심으로 된 중앙 집중형, 각 노드는 중앙에 위치한 노드와 일대일 통신 <br>
장점 : 장애 발견 쉬움 <br>
단점 : 중앙 노드 장애 발생 시 네트워크 전체 영향 <br>

- 링형 <br>
링 형태를 이루고 있는 형태 <br>
장점 : 연결 관리 서버 불필요 <br>
단점 : 노드의 추가 삭제가 용이하지 않음, 하나의 오류가 네트워크 전체에 영향을 줄 수 있음 <br>

- 트리형 <br>
하나의 노드에 여러 개의 노드가 트리 형태로 연결 <br>
장점 : 관리가 용이 <br>
단점 : 상위 회선에 문제 발생 시 하위에도 발생 <br>

- 메시형 <br>
모든 노드가 일대일 연결 <br>
장점 : 특정 노드의 장애가 전체 네트워크에 영향을 주지 않음 <br>
단점 : 비용이 많이 든다. <br>

### 교환망
- 회선 교환망 : 회선 자체 교환. 팩시밀리 전송. 시분할, 공간분할 교환방식. 연결성
- 메세지 교환망 : 메시지 단위 교환. 축적 방식으로 전송. 응답시간 느림. 실시간 데이터에는 부적합
- 패킷 교환망 : 메세지를 패킷 단위로 전송. 전송량 제어 및 속도 변환, 재전송. 블로킹 현상 없음. 비연결성

### CSMA/CD
Carrier Sense Multiple Access with 
Collision Detection의 약자.
802.3 유선 LAN, 버스형, 트리형
데이터 충돌을 방지하기 위해 송신 데이터가 없을 때 송신
충돌이 감지되면 멈추고 일정 시간 후 재전송

### CSMA/CA
Carrier Sense Multiple Access with 
Collision Avoidance
802.11 무선LAN
충돌 회피. 전송 전 채널 유휴 여부 확인. 일정 시간 대기 후 전송

### 토근 패싱 방식
토큰이라는 제어 비트를 송신. 해당 토큰을 확보하여 통신하는 방식. 제어 신호가 각 노드들을 순차적으로 옮겨가며 데이터를 전송. 충돌이 발생하지 않음 설치 비용이 비싸고 복잡함
- Token Ring <br>
802.5, 모든 노드에 물리적인 링이 연결, 토큰이 링을 따라 순차적으로 전송
- Token bus <br>
802.4, 모든 노드에 버스형 토폴로지 이용. 케이블 양 끝에 신호 바인딩을 막기 위한 터미네이터 장치 사용

502 - 요청 자체가 틀린 경우 <br>
